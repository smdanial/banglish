# Banglish Voice

A tiny, mobile-friendly web page for collecting **Banglish speech data**: volunteers read short Banglish sentences (Bangla written in Latin letters, often mixed with English words), correct the text to what they actually said, and submit. Audio goes to Supabase Storage, metadata to a Supabase table. An export script turns everything into a 16 kHz mono WAV dataset with a `manifest.csv`.

- No framework, no server: one HTML page, ~13 KB of plain JavaScript (≈5 KB gzipped), plus `prompts.json`.
- Works in Chrome on Android and Safari on iPhone (iOS 14.3+). Must be served over **https** for the microphone.
- The public key in the page can **only insert**. It cannot read, list, download or delete anything (row-level security, see `supabase/setup.sql`).

## How it works for a volunteer
1. **Consent** (English + Bangla). Nothing records until they tick **I agree**.
2. **Optional info**: age range, region/district (all 64 districts), phone model. A random anonymous `speaker_id` is created and kept in the browser (localStorage). "Someone else using this phone?" starts a fresh speaker (and shows consent again).
3. **Record**: one sentence at a time, big **Record/Stop** button (auto-stops at 30 s), **Play**, **Re-record**.
4. **"What you actually said"** box, prefilled with the sentence – edit it if they said something different.
5. **Submit & next** uploads the audio + row and shows the next sentence. Progress counter (e.g. `7/50`) and **Skip**. After 50 a thank-you screen offers "Record more".

Sentences are shuffled per speaker but dealt round-robin across categories, so even a short session covers every category.

## Repo layout
| Path | What it is |
|---|---|
| `public/` | The website (`index.html`, `app.js`, `style.css`, `_headers`). `config.js` and `prompts.json` are generated by the build. |
| `data/prompts.json` | 300 Banglish prompts (5–15 words), 27–28 per category, each with `id`, `category`, `text`. |
| `supabase/setup.sql` | One-time SQL: table, private bucket, row-level security. |
| `scripts/build.mjs` | Build step (`npm run build`): writes `public/config.js` from env vars, copies prompts. Refuses admin keys. |
| `scripts/export_dataset.py` | Downloads all audio → 16 kHz mono WAV + `manifest.csv`. Uses the admin key. |
| `scripts/check_setup.py` | Verifies the Supabase security rules (public key = insert only). |
| `scripts/qc_dataset.py` | Quality check of an exported dataset → `reports/qc_report.md` + `reports/flagged.csv`. |
| `scripts/make_splits.py` | Train/dev/test split by speaker, from `docs/SPLITS.md` → `splits.json`. |
| `docs/SPLITS.md` | Which speakers are in test and dev (you fill this in). |
| `tests/` | Synthetic sample data generator, `sample_data/`, unit tests (`python3 -m unittest discover -s tests`). |
| `docs/SUPABASE_SETUP.md` | Step-by-step Supabase setup for non-coders. |
| `docs/DEPLOY.md` | Step-by-step deploy to Vercel or Cloudflare Pages. |
| `.env.example` | All environment variables, with explanations. |

Prompt categories: `meetings_times`, `expenses_taka`, `people_names`, `places_bd`, `numbers_phone`, `shopping`, `travel`, `food`, `study_exams`, `family_chat`, `code_mixed_english`.

## Setup (once)
1. **Supabase** – follow [docs/SUPABASE_SETUP.md](docs/SUPABASE_SETUP.md): create project → run `supabase/setup.sql` → copy keys.
2. **Deploy** – follow [docs/DEPLOY.md](docs/DEPLOY.md) (Vercel or Cloudflare Pages). Set `SUPABASE_URL` and `SUPABASE_ANON_KEY` in the host's environment variables.
3. **Test on your phone** – open the link, accept consent, record and submit 3 sentences, then check **Table Editor → recordings** (3 rows) and **Storage → recordings** (3 files) in Supabase.

### Environment variables
| Variable | Used by | Notes |
|---|---|---|
| `SUPABASE_URL` | site + scripts | `https://<project>.supabase.co` |
| `SUPABASE_ANON_KEY` | site | publishable (`sb_publishable_…`) or anon (`eyJ…`) key. Public by design, insert-only. |
| `SUPABASE_SERVICE_ROLE_KEY` | export/check scripts only | secret (`sb_secret_…`) or service_role key. **Never** put it in Vercel/Cloudflare or the page. |
| `SUPABASE_BUCKET` | site + scripts | default `recordings` |
| `SESSION_GOAL` | site | sentences per session, default `50` |
| `CONTACT_TEXT` | site | optional contact line on the consent screen |

Locally, put them in a `.env` file (copy `.env.example`; `.env` is git-ignored).

### Run locally (optional, for developers)
```bash
cd data-collector
cp .env.example .env   # fill in values
npm run dev            # builds, then serves http://localhost:8000 (localhost counts as secure, so the mic works)
```
Needs Node 18+ and Python 3. There are no npm dependencies.

## Sharing the link with volunteers
1. Use the **production** link (e.g. `https://banglish-voice.vercel.app`) – not a Vercel *preview* link, which asks for a Vercel login.
2. Turn it into a short link or QR code if you like (any free QR generator works).
3. Send a message such as:

   > Assalamu alaikum! We're building speech recognition for Banglish. Could you record a few sentences on your phone? It takes ~10 minutes, no name needed.
   > 👉 https://banglish-voice.vercel.app
   > Tips: open in Chrome (Android) or Safari (iPhone), sit somewhere quiet, hold the phone normally, speak naturally. If you say a sentence differently, just fix the text before submitting. 
   >
   > আসসালামু আলাইকুম! আমরা বাংলিশ কথা চেনার প্রযুক্তি বানাচ্ছি। ফোনে কয়েকটা বাক্য রেকর্ড করে দেবেন? ১০ মিনিটের মতো লাগবে, নাম লাগবে না। শান্ত জায়গায় বসে স্বাভাবিকভাবে পড়ুন। অন্যভাবে বললে জমা দেওয়ার আগে লেখাটা ঠিক করে দিন।

4. Tips for good data:
   - Ask people to use their **own phone**; if a phone is shared, the next person taps **"Someone else using this phone?"** so they get their own speaker ID.
   - If WhatsApp/Facebook opens the link in its in-app browser and the mic doesn't work, tap ⋮ → **Open in Chrome** (or Safari).
   - If the mic was blocked by mistake: tap the lock icon next to the address → **Microphone → Allow**, then reload.
   - Mixing ages, regions and phone models makes the model better – share in different groups.
5. Watch progress in Supabase (**Table Editor → recordings**). Remember free Supabase projects pause after 7 days with no activity.

## Exporting the dataset
On your own computer (needs Python 3.8+ and [ffmpeg](https://ffmpeg.org/download.html)), with `SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY` in `.env`:
```bash
cd data-collector
python3 scripts/export_dataset.py            # → dataset/wavs/*.wav + dataset/manifest.csv
python3 scripts/export_dataset.py --out mydata --keep-original
```
`manifest.csv` columns: `path, speaker_id, prompt_text, actual_text, category, duration` (duration in seconds, measured from the WAV), then `prompt_id, phone_model, age_range, region, recording_id, created_at`. Re-running only downloads new recordings. Use `actual_text` as the transcript for training.

## Quality check and train/dev/test splits
Needs `pip install numpy`. Run from the `data-collector` folder on the exported dataset:
```bash
python3 scripts/qc_dataset.py --dataset dataset          # → reports/qc_report.md + reports/flagged.csv
python3 scripts/make_splits.py --dataset dataset --config docs/SPLITS.md --exclude reports/flagged.csv   # → splits.json
```
- Read `reports/qc_report.md` first: the "Problems to fix" list at the top says what to do. `flagged.csv` opens in Excel or Google Sheets; `suggested_action` is **remove**, **fix text** or **listen**.
- Before running `make_splits.py`, list your test and dev speaker_ids in `docs/SPLITS.md`. Every other speaker goes to train. A speaker listed in both test and dev stops the script. It warns when a category has fewer than 15 test clips. `--exclude` leaves out clips marked **remove**.
- `reports/`, `splits.json` and all audio files are git-ignored, so they never get committed by accident.
- To try the scripts without real data: `python3 tests/make_sample_data.py`, then add `--dataset tests/sample_data --config tests/sample_data/SPLITS.md` to the commands above.

## Privacy & security notes
- No names, emails or IPs are stored by the app. `user_agent` is stored (browser/phone info) as requested.
- The anonymous speaker ID is shown at the bottom of the page; a volunteer can send it to you to ask for their recordings to be deleted (delete their rows in Table Editor and their `spk_…` folder in Storage).
- The admin key is only read from environment variables by the scripts and is never sent to the browser; the build fails if an admin key is configured as the public key.
